## Usage

```tsx showLineNumbers
import {
  Questionnaire,
  QuestionnaireActions,
  QuestionnaireChoice,
  QuestionnaireChoices,
  QuestionnaireError,
  QuestionnaireItem,
  QuestionnaireSubmit,
  QuestionnaireTitle
} from "~/components/ui/questionnaire"
```

```tsx showLineNumbers
<Questionnaire steps={["direction"]} required={["direction"]}>
  <QuestionnaireItem value="direction">
    <QuestionnaireTitle>What should we prototype next?</QuestionnaireTitle>
    <QuestionnaireChoices>
      <QuestionnaireChoice value="search">Search</QuestionnaireChoice>
      <QuestionnaireChoice value="navigation">Navigation</QuestionnaireChoice>
    </QuestionnaireChoices>
    <QuestionnaireError />
  </QuestionnaireItem>
  <QuestionnaireActions>
    <QuestionnaireSubmit>Submit</QuestionnaireSubmit>
  </QuestionnaireActions>
</Questionnaire>
```

Pass ordered question IDs as `steps`, and required IDs as `required`. Each `QuestionnaireItem` has a matching `value`. Choices default to a radio group; `multiple` uses a checkbox group. `QuestionnaireInput` edits a text answer. `onComplete` receives a record of strings or string arrays. `value` and `onValueChange` control answers; `step` and `onStepChange` control navigation. Required answers prevent Next, Skip, and completion. Titles, descriptions, progress, errors, and focus connect to the active step. This Solid composition replaces the React-only questionnaire package.

## Composition

```text
Questionnaire
├── QuestionnaireProgress
├── QuestionnaireItem
│   ├── QuestionnaireTitle
│   ├── QuestionnaireDescription
│   ├── QuestionnaireChoices
│   │   ├── QuestionnaireChoice
│   │   └── QuestionnaireInput
│   └── QuestionnaireError
└── QuestionnaireActions
    ├── QuestionnairePrevious
    ├── QuestionnaireSkip
    ├── QuestionnaireNext
    └── QuestionnaireSubmit
```

Questionnaire owns the ordered items, active item, answer state, validation,
progress, and navigation. The containing page, card, dialog, or drawer owns
close and cancellation behavior, persistence, transport, and branching.

## Server Rendering

The active item, progress, actions, and answer shortcuts render on the server
from `steps` and the default answers. Use `useQuestionnaire` to read the active step and answers when building custom controls.

## Shortcuts

Assign a letter or number key to each answer with `shortcuts`. Each choice shows its key, and pressing it selects the choice in the active item. Keys are case-insensitive and follow the order of the choices: `"letters"` assigns A to Z, and `"numbers"` assigns 1 to 9. Typing in a text field does not trigger shortcuts.

## Accessibility

`QuestionnaireItem` renders a `fieldset`, and `QuestionnaireTitle` renders its
`legend`. Descriptions and active errors are associated with the current item,
and invalid items and answer controls expose `aria-invalid`.

Fixed choices preserve native radio and checkbox behavior. Progress is exposed
as a named progressbar, navigation uses real buttons, and inactive items and
actions are hidden and inert. Successful navigation focuses the newly active
item; failed validation focuses an available answer control.

Always give `QuestionnaireInput` an accessible name with a visible label,
`aria-label`, or `aria-labelledby`. A visible label lets readers identify what each field asks for.

## Unstyled

Use native forms and `useQuestionnaire` to build custom controls around the questionnaire state.

## API Reference

The root takes `steps`, `required`, `value`, `defaultValue`, `step`, `defaultStep`, and `shortcuts` (`"letters"` or `"numbers"`). Subscribe with `onValueChange`, `onStepChange`, and `onComplete`. Navigation buttons also accept the Button `size` and `variant` props. `QuestionnaireActions` is a layout wrapper.
